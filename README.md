# MINIX 3.4.0 — amd64 UEFI branch

This repository is a fork of https://github.com/nnonaka/minix/ with UEFI
boot support and an x86_64 (amd64) port.

## Build environment

The cross-build environment is Ubuntu 26.04.

## Build an amd64 UEFI installation ISO

Build the release sets first, then create the ISO:

```sh
sudo apt install xorriso
./build.sh -U -u -m amd64 -O ../build release
./build.sh -U -u -m amd64 -O ../build iso-image
```

The resulting image is:

```
../build/releasedir/images/Minix-3.4.0-x86_64-install.iso
```

The amd64 `iso-image` target invokes
`releasetools/x86_64_uefi_cdimage.sh`. It builds a FAT32 EFI El Torito boot image containing
`EFI/BOOT/BOOTX64.EFI`, and an ISO9660 filesystem containing the amd64
kernel, boot modules, boot menu and release sets. The boot menu uses the
64-bit UEFI loader and the Multiboot2 entry point; this is not the legacy
32-bit BIOS image generated by `releasetools/x86_cdimage.sh`.

For direct invocation after a release build, run
`OBJ=../build bash releasetools/x86_64_uefi_cdimage.sh`. The helper defaults
to reusing existing build outputs; set `CREATE_IMAGE_ONLY=0` to have it run
the release build before packaging. Paths and image settings can be overridden
with `OBJ`, `DESTDIR`, `RELEASEDIR`, `SETS_DIR`, `CROSS_TOOLS`,
`WORK_DIR`, `IMG`, `XORRISO`, and `EFIMB`.

### Installing MINIX to a UEFI disk

The amd64 UEFI ISO includes an interactive installer at
`/usr/sbin/minix-install`. Build the release and ISO as described above,
boot the ISO in UEFI x86-64 mode, open a root shell, and run:

```sh
/usr/sbin/minix-install
```

The installer reads the release archives from
`/usr/amd64/binary/sets`. It creates a GPT with a 64 MiB FAT32 EFI System
Partition (`c0d0p0`) and an MFS root partition (`c0d0p1`), installs the
available release sets plus the amd64 kernel and boot modules, and writes
the EFI loader and installed-system boot menu to the ESP. The root filesystem
uses MFS and the installation does not create a swap partition.

**Current limitation:** the installer targets the first MINIX disk,
`c0d0`, because the prebuilt UEFI boot menu uses `rootdevname=c0d0p1`.
Make sure the disk you intend to erase is enumerated as `c0d0`. You may
preselect it with `--disk c0d0`; the destructive confirmation is still
required.

**Destructive operation:** all existing data and partitions on `c0d0`
will be erased. The disk must not be mounted. Before partitioning, the
installer requires you to type the exact confirmation `ERASE c0d0`.

The older `distrib/amd64/installimage` target still follows the legacy
`sysinst` path and is not the supported installer entry point. Use the
amd64 UEFI ISO described above. The amd64 port and installer are experimental;
test in a VM before installing on physical hardware.

## Existing amd64 live image

```sh
./build.sh -U -u -m amd64 -O ../build live-image
```

The live disk image is produced under
`../build/distrib/amd64/liveimage/emuimage/`.

## Current port status

- i386 and amd64 source/build support.
- UEFI boot via `bootia32.efi` and `bootx64.efi`.
- Multiboot2 kernel boot and login prompt on the tested live image.
- POSIX test status recorded by the port author: 94/97 passed.

The amd64 port and the installation media are experimental; test the ISO in
a VM before writing it to physical media.
